### 用户报告与判据

用户实测：`results/e11-ece-20x20/`（330 MB）与 `results/e11-ece/`（11.7 MB）的 SML 在
AEDT `Tools → Project Tools → Import Twin Builder Models` 均报 **action failed**。
用户指示：改用官方教程脚本 `MotorCAD_ECE_Export.py`。

### 根因（对照官方产物实测）

用随 Motor-CAD 安装的官方脚本在同一次 FMC 数据上导出，得到对照：

| 文件 | 数字个数 | 字节 |
|---|---|---|
| 官方脚本产物 | 17,237 | 174,036 |
| 我们的产物（8×8） | 1,079,957 | 11,715,457 |

倍数 81 = 电流对数（9×9）。`_pwl_body` 在写 pwl 表时把**整列**（3,321 个值）当成每个电流对的
数据，而官方每个电流对只写自己的 `map_points`（41）个值。Twin Builder 按声明的 `41` 解析，
收到 3,321 个 → 直接拒绝。

### 逐条对齐官方时另发现的两处偏差

1. **输出列次序错**：官方第 3、4 列是 Ψ0（恒 0）与**转矩**；我们错写成相位超前角与转子位置。
2. **收尾记号错**：官方最后一列后直接接 `) LINEAR LINEAR PERIODIC\`，不补续行；
   我们多补了续行，且把收尾引号放到了 `)` 之前（应为 ` DEEPSPLINE" );`）。

另有一处空格差异（`N7:=N_23 \` 官方在反斜杠前有一个空格）。

### 验收判据

我们的 SML 与官方脚本产物在归一化模型名后**逐字符相同**（172,540 字符全等）。
这条判据不依赖 GUI 导入，可机检。

### 验证与收口

| 项 | 读数 |
|---|---|
| 与官方产物逐字符比对 | 归一化模型名后 172,540 字符**完全相同** |
| 8×8 数字总量 | 17,237，与官方**完全相等** |
| 20×20 数字总量 | 92,159，理论值 90,867（比值 1.014，余量为端口常数） |
| 产物体积 | 8×8 SML **11.7 MB → 170 KB**；20×20 SML **330 MB → 907 KB** |
| 单测 | 32 项通过（新增 `test_pwl_data_volume_is_not_multiplied` 钉住数字总量） |
| ruff | 全清 |

**体积结论修正**：此前按错误产物推算的「SML 随网格平方增长、330 MB 起」不再成立。
真实体积 ≈ 每负载点 0.7 KB，41×41 约 3.6 MB、61×61 约 7.6 MB、81×81 约 13 MB，
体积不再是网格规格的约束。

**未验证项**：Twin Builder 的实际导入未做机检——`ConvertSMLtoSMT` 通过 COM 调用时
对两份文件（官方与我们的）都报 `0x80070003` 路径错误，属调用方式问题而非 SML 问题，
本轮放弃该路径。正确性以「与官方产物逐字符一致」为准，实际导入需用户在 GUI 复核。
